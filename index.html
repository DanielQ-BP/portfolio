07 · Capstone Project

ParkSpot — Mobile Parking Marketplace

Project Summary

ParkSpot is a cross-platform mobile application that connects drivers searching for parking in urban areas with property owners who have unused parking spaces available for short-term rental. Built with React Native (TypeScript) on the front end, a Node.js / Express REST API on the back end, and PostgreSQL (with PostGIS) as the database, ParkSpot handles real-time spot discovery via map markers, role-based authentication for Drivers and Space Owners, reservation management with grace-period and overstay logic, and Stripe-integrated payment processing — all containerized with Docker and deployable to AWS / Azure / GCP.

Project Vision

Urban drivers waste significant time and money hunting for parking. ParkSpot's vision is to unlock the hidden capacity of privately owned but underutilized spaces — driveways, garage spots, and lots — turning them into a community-driven, on-demand parking network. Success means a driver can open the app, locate a verified nearby spot, reserve it in under 60 seconds, and arrive to find it ready. For owners, it means passive income from an asset they already have. Long-term, ParkSpot aims to reduce urban congestion and emissions by shortening the search radius drivers travel before parking.

Business Requirements

Core requirements driving the project scope include: dual-role user authentication (Driver and Space Owner accounts); parking spot CRUD for owners, including availability scheduling; geolocation-based spot search with map-marker UI for drivers; reservation lifecycle management — booking, confirmation, check-in, grace period, overstay detection, and penalty charges; push notifications for reservation events and expiry alerts; Stripe payment simulation for booking transactions; and an Admin / Customer Care dashboard for dispute resolution and user management.

Requirements Analysis & Design

Requirements were gathered through stakeholder interviews and documented in a formal Software Requirements Specification (SRS v1.0, Nov 2025). The database schema centers on five core entities — Users, ParkingSpots, Availability, Reservations, and Transactions — with PostGIS extensions enabling geospatial search queries. The REST API is organized around these resources with JWT middleware enforcing role-based access control. The React Native component hierarchy mirrors the user journey: Auth → Home/Map → Spot Detail → Booking → Confirmation → Active Reservation, with a parallel Owner flow for listing management.

Wireframes / UI Mockups

High-fidelity UI mockups were designed in Figma, covering the Login, Register, Home (map view), Spot Listings, Booking flow, and Reservation Status screens for both Driver and Space Owner roles. The design system uses a clean, map-centric layout with a bottom-sheet pattern for spot details.

View Figma Mockup →

System Implementation

The mobile front end is built in React Native with TypeScript. The back end uses Node.js + Express.js serving a REST API, with PostgreSQL + PostGIS for relational and geospatial data. Authentication uses bcrypt password hashing and JWT tokens. The full stack is containerized via Docker Compose orchestrating the API service, database, and future admin tooling. As of Sprint 7 (March 2026): React Native navigation and role-based login are complete; PostGIS-powered spot search is live in staging; Stripe payment integration and the Admin dashboard are in final testing.

React Native TypeScript Node.js Express PostgreSQL PostGIS Docker JWT Stripe
